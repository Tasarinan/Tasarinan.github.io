# OC-记忆会话与上下文装载

这篇是我基于项目实践与资料交叉阅读整理的学习笔记，目标不是复述概念，而是沉淀可直接复用的工程动作与判断标准。

记忆不是越记越多，而是按会话装载。Context Manager 的职责是决定这一轮读哪些文件。把 MEMORY.md、全部日报和所有技能一次性塞进窗口，看起来「更懂你」，其实是在用噪声换偶然的命中。

## 一、目标与边界

本篇解决：短记忆、长记忆、会话日志如何分工，以及主会话启动时的装载顺序。不讨论向量库品牌对比。

三层记忆：

1. 会话记忆：当前窗口里的对话。会话结束即消失，除非被压缩或摘进日报。
2. 短期记忆：`memory/YYYY-MM-DD.md`。默认只装今天和昨天。
3. 长期记忆：`MEMORY.md` 里的稳定事实、偏好、重要决策。主会话才必读，建议控制体量，避免变成小说。

另外还有人格与用户档案：`SOUL.md`、`USER.md`。它们不是记忆，是每次都要的身份约束。把临时结论写进 SOUL，等于污染人格版本。

OpenClaw 用 Markdown 作真相源，向量检索是索引而不是第二份记忆。索引坏了可以重建；Markdown 乱了，人就无法审计。

## 二、结构 / 分层模型

工作区主会话的推荐顺序已经写在 `AGENTS.md`：先跑 Context Manager → 永远读 SOUL 和 USER → 按场景读必需文件 → 主会话再读 MEMORY → 按需查经验库。这不是仪式，是预算阀。

Context Manager 按首句识别场景，例如投资分析、代码、闲聊、新闻、健康检查。每个场景有必需文件、可选文件、推荐技能。可选文件按使用频率和衰减加载，旧日报自动压缩归档。

错误的装载模型是「全量祝福」：SOUL + USER + MEMORY + 全部日报 + 全部技能。投研场景下这会把代码技能和健康检查一起带上。正确模型是「场景切片」：闲聊不读投资档案；写技能不读持仓结构。切片会漏偶尔需要的冷知识，那是检索的工作，不该靠把所有文件常驻窗口来赌。

压缩（compaction）发生在窗口不够时。压缩产物必须可回放：谁在何时把哪些要点写入了日报。静默丢细节，比超窗口更难查。

## 三、工程动作

1. 规定主会话装载清单，写成可执行步骤，而不是「尽量读相关文件」。无场景时只读 SOUL / USER，不读 MEMORY 以外的专题档案。
2. 给 MEMORY.md 设硬上限（行数或 token）。超限先归档到日报或经验库，不准继续追加。
3. 日报只记「今天发生的、明天可能用到的」。把永久偏好提升到 MEMORY 或 USER，把一次性推理留在会话。
4. 子会话默认不读 MEMORY。子代理做切片分析时，只带任务说明书和证据文件，避免把用户私人偏好泄漏进工具轨迹。
5. 每次装载记录文件列表和总 token。这是唯一能证明 Context Manager 有没有工作的证据。
6. 对「继续昨天那个」类请求，显式加载昨天的日报，而不是把七天日志全倒进去碰运气。
7. 向量检索只用于找旧日报和经验条目，命中后仍要读原文。禁止只把检索摘要当事实。
8. 晋升规则写清楚：一条日报事实被引用两次以上，才考虑进入 MEMORY。一次聊天里的金句不要当天晋升。
9. 装载失败要可见：Context Manager 挂了必须打日志并走最小集，而不是静默退化成全量或空装载。空装载会让模型装成通用助手，全量则会爆预算。

过关口径：同一句投研问题和同一句闲聊，装载列表必须不同；闲聊列表里不应出现投资档案。若两类请求的文件清单一致，Context Manager 就只是摆设，记忆系统仍在吃全盘祝福。

## 四、常见失败模式

1. MEMORY 无限生长，主会话未开口已经半窗。对策：上限 + 定期晋升/降级。
2. 所有会话都当主会话，子任务也读完整人格和投资档案。对策：主会话才读 MEMORY。
3. 场景检测失败就回退到全量加载。对策：失败应回退到最小集（SOUL + USER），不是最大集。
4. 压缩没有原文指针，复盘时只剩「用户好像提过」。对策：压缩块必须带日期和文件名。
5. FAQ：AI「不记得昨天」。常见是没加载昨天的日报，或日志写在了会话 jsonl 却从未晋升。对策：验收看装载列表，不看模型口头保证。

## 五、建议指标

装载日志是这些指标的唯一证据，口头「我读过了」不算。建议跟踪：

- 主会话平均装载 token / P95 装载 token
- 有效 token 占比（被引用的文件字符 / 装载字符）
- 场景检测准确率（抽检）
- 检测失败时是否回退到最小集（应为 100%）
- MEMORY.md 行数或 token，是否低于上限
- 「不记得」投诉中，实际未装载昨日日报的比例

## 六、结论

记忆系统的质量由装载策略决定，不由文件数量决定。Context Manager 把场景变成文件清单，预算才可控，人格才稳定。记更多只是手段；每次只带这一轮用得上的，才是目标。清单应能在日志里原样复现，否则「按场景加载」无法审计。

## 学习者复盘

这轮整理里，我刻意保留了三类内容：
1. 真正会踩坑的决策点：场景失败回退最小集，不是全量。
2. 可以落到监控面板的指标：装载 token、有效占比、MEMORY 体积。
3. 能在下次项目里直接复用的流程模板：AGENTS.md 式启动顺序。

后续继续学习时，我会优先补两块：
- 用一周装载日志验证场景检测误判长什么样。
- 对比「只读今天」与「今天+昨天」在连续任务上的成功率边界。
