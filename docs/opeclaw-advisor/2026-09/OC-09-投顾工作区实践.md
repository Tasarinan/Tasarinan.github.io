# OC-投顾工作区实践

这篇是我基于项目实践与资料交叉阅读整理的学习笔记，目标不是复述概念，而是沉淀可直接复用的工程动作与判断标准。

本文讨论系统设计，不构成投资建议，不涉及任何具体买卖点或收益承诺。

投顾工作区是一组可审计模块：投资档案、持仓视图、监控、技能包。它不是把「你是顶级投资者」写进 prompt 就结束的全能人格。模块拆不开，结论就无法复核。

## 一、目标与边界

目标：让助手在投研场景下稳定地取数、记录假设、提示风险。非目标：代替交易系统下单，或输出「现在该买」。

模块边界：

- 档案：风格标签、持有周期偏好、风险承受、关注赛道。这是约束，不是行情。
- 持仓视图：结构化跟踪「在看什么、仓位角色是什么」，刷新时间必须可见。
- 监控：规则化预警（披露、价格阈值、数据源中断），不是盘感推送。
- 技能包：采集 / 拆解 / 综合 / 风控，见 OC-05。
- 人格：SOUL 只约束口吻（直接、要有来源）。禁止在人格里写标的清单。

真实工作区会有一份投资档案，里面出现过风格字段和持仓表。公开笔记只保留字段设计，不转载具体标的、盈亏或账户信息。需要举例时用虚构的「标的 A / 赛道 X」。字段可以公开讨论，数字和名单不可以。

## 二、结构 / 分层模型

一次投研请求的推荐路径：

1. Context Manager 识别 `investment_analysis`。
2. 装载 SOUL、USER、档案摘要（不是全市场新闻）。
3. 按问题选择技能层：只要估值就不要跑完整尽调。
4. 数据源写出处与时间戳。无时间戳的数字视为无效。
5. 风控层输出红旗和不确定性，而不是把红旗改写成信心。
6. 主会话汇总为「观察 / 假设 / 待验证 / 风险」，四段缺一不可。

持仓视图与监控必须和档案分开。档案变更是投资政策；视图刷新是数据作业；监控触发是事件。三者写在同一个 Markdown 大文件里，权限和刷新节奏会缠死。

权限：子代理可以读脱敏后的视图字段（赛道、角色），不应读完整券商导出。对外 Channel 默认不加载档案。

## 三、工程动作

1. 把档案做成字段表：风格、周期、止盈/止损习惯、风险偏好、关注赛道。字段比散文好 diff。
2. 给每个数据源登记：名称、刷新频率、失败时的降级（延迟、缺失、禁止推断）。
3. 持仓视图只保留角色字段（核心 / 观察 / 试验），不在助手输出里复述数量和成本。
4. 监控规则写成可测试的条件：「源中断超过 N 分钟告警」，而不是「感觉市场不对」。
5. 主会话输出模板强制四段。模型爱写「强烈看好」时，模板会把它赶回「假设」。
6. 决策若被采纳，记入经验库类型 `decision`，带日期和否决条件。未采纳的也记，避免只存成功学。
7. 定期访问控制检查：哪些 Channel、哪些子代理读过档案。多余读取当事件。
8. 把「关注赛道」和「当前观点」分开。赛道是政策字段，观点必须带日期并会过期。过期观点继续当约束，会把档案变成旧研报。
9. 对外输出前做脱敏扫描：券商名、账号、精确数量、未公开的成本。扫到就阻断，而不是靠模型自觉。

过关口径：一份投研回复可以在不打开档案原文的情况下被第三人复核——出处、时间、假设、风险四段齐全，且不出现可识别的账户细节。复核者若必须「熟悉这个用户才能看懂」，工作区就还是私人日记，不是可审计系统。

## 四、常见失败模式

1. 人格宣称「顶级投资者」，分析却无来源无日期。对策：无来源数字直接作废。
2. 把档案里的标的表当作推荐列表对外复述。对策：对外通道不装载档案；对内也脱敏。
3. 监控与分析混在一次长对话，告警被模型润色成故事。对策：监控走独立规则引擎或独立技能，原文上屏。
4. 数据源失败时模型「估算一个数」。对策：源失败只能输出降级状态，禁止填空。
5. 工作区路径或账号写进笔记和聊天。对策：文档用占位符；密钥只在环境变量。

## 五、建议指标

投研质量先看出处和风控段，再看文笔。建议跟踪：

- 分析回复中带出处与时间戳的比例（目标 100%）
- 数据源刷新延迟 P95
- 源失败后的禁止推断遵守率
- 风控段缺失率（目标 0）
- 档案被非投研场景装载的次数（应接近 0）
- 对外通道触达档案字段的次数（目标 0）

## 六、结论

投顾工作区的可靠性来自模块和审计，不来自更自信的口吻。档案约束行为，视图与监控提供可刷新的事实，技能包产出可回放的中间件，主会话只做汇总与风控。任何把这四件事揉进一段 prompt 的做法，都经不起下一次复盘，也经不起第三人抽检。

## 学习者复盘

这轮整理里，我刻意保留了三类内容：
1. 真正会踩坑的决策点：无时间戳数字作废。
2. 可以落到监控面板的指标：出处完整率、源延迟、档案越权装载。
3. 能在下次项目里直接复用的流程模板：观察 / 假设 / 待验证 / 风险。

后续继续学习时，我会优先补两块：
- 用一次源中断演练，看模型会不会偷偷补数。
- 对比「字段化档案」与「散文档案」在 diff 和误装载上的差异。
