# OC-技能编排与投顾技能包

这篇是我基于项目实践与资料交叉阅读整理的学习笔记，目标不是复述概念，而是沉淀可直接复用的工程动作与判断标准。

Skill 是编排说明书，Tool 是原子动作。投顾能力应该做成技能包，而不是写进 SOUL。把研报流程焊在人格里，既无法测试，也无法按市场关掉。

## 一、目标与边界

本篇只界定：什么是 Skill、什么是 Tool、投研类能力如何分层隔离。不写 ClawHub 商店浏览教程。

对照：

- Tool：无状态的单步能力，读文件、搜索、跑脚本、发消息。
- Skill：Markdown 指令，告诉模型何时用哪些 Tool、输入输出是什么、失败怎么收。

Skill 可以维护任务上下文，Tool 不应该偷偷变成工作流引擎。需要编程的新原子能力才新写 Tool；能用现有 Tool 拼起来的，优先写 Skill。

投顾相关边界：技能产出的是带来源的分析材料、风险清单、待确认问题。技能不下达买卖指令，不把「目标价」写成执行单。

## 二、结构 / 分层模型

建议四层，而不是「一个全能分析 skill」：

1. 采集层：搜索、浏览器、公告/行情抓取。例子：baidu-search、agent-browser、auction-data-collector。
2. 拆解层：财报、估值、行业对比、宏观情绪。每个只做一种切片。
3. 综合层：完整拆解、尽调提纲。只允许调用拆解层的产出，不允许直接扫全网。
4. 风控层：红旗扫描、合规提示。综合层通过后必须经过这一层才能交给主会话。

工作区里已经按这个方向长出来：A 股分析、全市场分析师、美股下的财报/估值/行业/红旗等子技能。问题通常不是没有技能，而是主会话一次加载太多，导致误触发和 token 浪费。

触发方式要写死：关键词、场景检测、或人工点名。不要指望模型在 50+ 技能里「自己挑对」。Context Manager 按场景推荐技能，是在补这一刀。

权限上，Skill 声明需要什么，Sandbox 和审批决定实际给什么。编码类技能默认沙箱；投研采集技能限制可写路径，避免把下载文件写进密钥目录。

## 三、工程动作

1. 盘点现有技能，按采集 / 拆解 / 综合 / 风控打标签。贴不进四层的，多半是 SOUL 或闲聊，不该叫 Skill。
2. 每个 SKILL.md 固定五个段落：何时触发、输入字段、步骤、输出字段、禁止事项。禁止事项至少包含「不给买卖建议」。
3. 综合层禁止直接调浏览器。它只能消费拆解层已经写好的中间文件。这样失败可以回放到某一份切片。
4. 主会话默认只加载采集入口和风控，不加载全部美股子技能。具体拆解由场景或子代理按需启用。
5. 给技能包做版本：改步骤就升版本，主会话记录用的是哪一版。没有版本的技能无法解释「为什么这周结论变了」。
6. 用同一只虚构标的跑通四层，检查中间产物是否落盘。只看最终长文，技能包等于不可测。
7. 把「写进 SOUL 的操作步骤」迁出。SOUL 只保留沟通约束；步骤迁到 Skill 后，人格 diff 应接近为零。
8. 给风控层一票否决：综合层产出缺少出处或风险段时，主会话不得当完成件发出。否决要留下原因，方便改技能而不是改口吻。
9. 技能下线比上线更重要。两周无命中且有替代切片的技能，移出默认推荐，避免目录膨胀把触发再次打回「全加载」。

过关口径：同一虚构标的跑两遍综合任务，中间产物路径稳定、风控段都在，且 SOUL 文件无 diff。如果两遍结论差异只能用「模型心情」解释，说明技能包还没有把流程从随机性里抽出来。

## 四、常见失败模式

1. 一个「全市场分析师」技能内嵌采集、估值、风控。任一网站改版，整条链不可用。对策：按层拆文件，综合层只编排。
2. 技能与工具同名，团队沟通时以为写了 Skill 就有了新 API。对策：命名区分，Skill 用任务名，Tool 用动宾。
3. 触发词过宽，「分析一下」加载全部投研技能。对策：场景检测 + 显式技能名，宽触发只进采集层。
4. 技能在沙箱外跑 shell 下载。对策：采集层 allowlist，下载目录固定。
5. FAQ：安装了技能「没反应」。常见是未进入工作区技能目录、或未出现在场景推荐里。对策：验收看「是否被装载」，不只看文件是否存在。

## 五、建议指标

- 技能装载命中率：被推荐且真正被用到的比例
- 误触发率：加载了但步骤未执行，或执行了错误层
- 中间产物落盘率（拆解层输出可回放）
- 综合层跳过风控层的次数（目标 0）
- 单次投研任务的平均技能数（应有上限）
- 技能版本可追溯率

## 六、结论

技能系统让 OpenClaw 可扩展，但扩展的单位是「可测的流程切片」，不是更长的人格。投顾能力按采集、拆解、综合、风控分包之后，主会话才能保持冷静，SOUL 才能保持稳定。

## 学习者复盘

这轮整理里，我刻意保留了三类内容：
1. 真正会踩坑的决策点：投研流程不进 SOUL。
2. 可以落到监控面板的指标：误触发、跳过风控、中间产物落盘。
3. 能在下次项目里直接复用的流程模板：四层技能包 + SKILL.md 五段。

后续继续学习时，我会优先补两块：
- 对一次「综合层直接上网」的失败做根因，而不是只写分层原则。
- 对比单技能大而全与多技能编排在 token 和可维护性上的真实差值。
