## 一、网关设计的三个第一性原则

### 1.1 状态分离：可丢与不可丢分居两层

```
可丢状态（连接、心跳、鉴权缓存、发送缓冲）→ 网关进程内，随进程生死
不可丢状态（会话、消息、seq、路由）        → 业务层/存储层，跨进程存活
```

一切网关设计决策的源点。**无状态不是"没有状态"，是"状态死了能自动重建"**——kill 网关只损失重连，路由表 10 分钟内由心跳/下线事件收敛，消息在 MQ 与离线收件箱等它。这与 K8s 周的"无状态 Deployment + 状态外置"完全同构。

### 1.2 推拉结合：推送加速，拉取兜底

单靠推送（TCP/WS）永远无法承诺可靠——连接会断、缓冲会满、消费者会假死。架构师的答案从来不是"把推送做到极致可靠"，而是**承认推送不可靠，用拉取（HTTP + seq 区间）做可靠性地板**。这是"最终一致性优于强承诺"思想在网络层的表达。

### 1.3 按可丢性分级：一条消息的"服务等级"

```
消息不可丢（会话内容）→ 保序 + ACK + 离线补偿 + 背压时转离线
可丢可延迟（通知/在线状态）→ 背压时直接丢弃或合并
低延迟可丢（正在输入/已读回执）→ 直连 RPC 路径，不进可靠链路
```

同一套基础设施上跑三种服务等级——与 MQ 周的"核心/非核心流量隔离"、限流周的"分级限流"同构。**网关的智能不体现在"什么都推"，体现在"什么可以不推"**。

## 二、可靠性的统一模型：三件套跨域同构

| | IM 消息 | MQ 消息 | 支付交易 |
|---|---|---|---|
| 唯一标识 | client msgId | 消息 key/事务消息 | 幂等单号 |
| 确认重试 | ACK + 超时重发 | producer retry + acks | 渠道重试 |
| 对账补偿 | seq 缺口检测拉取 | 消费位点对账 | T+1 对账差错处理 |

**架构师的价值是识别不变量**：无论什么领域，"不丢不重"的解永远是这三件。面试从任一领域被追问，都可以横向举证另两个——这是跨域串联型候选人的标志性答法。

## 三、并发正确的两个隐形考点

### 3.1 下线路由清理的竞态

闪断重连（新连接写路由）与旧连接踢除（删路由）并发——无脑删除会误杀新记录。通则：**分布式删除必须校验归属/版本**。同一道理的变体：分布式锁释放校验持有者、缓存更新用 CAS、路由表删除带 gatewayId 比对。**"删自己的，别删别人的"在分布式环境下必须显式实现**。

### 3.2 错峰：把瞬时突发摊成时间窗口

重连风暴、缓存击穿、秒杀开始——同一时刻的集体行为是分布式系统最大的敌人。解法一族：随机抖动（重连指令 1~30s 随机）、 TTL 加随机（缓存过期打散）、预加载（鉴权缓存预热）。**网关把 10w 断连的恢复摊进 30 秒窗口，等于把洪峰降为 1/30**——量化理解"错峰"的杠杆率是架构师必备直觉。

## 四、容量与发布：工程成熟度指标

### 4.1 N+2 冗余的推理

容量问题从来不是"最大能扛多少"，是"**在故障与发布并存时还能扛多少**"：
- N 台满载 → 一台故障即雪崩（0 冗余）
- N+1 → 能扛故障但发布时无冗余（发布=一次受控故障）
- **N+2 → 故障与发布同时发生的最坏情况仍然安全**

3×10w 优于 1×100w 的论证同理：爆炸半径（死一台损失 1/3 vs 全部）、发布可行性、故障转移时间——**规模化的第一收益不是省机器，是缩小故障半径**。

### 4.2 连接迁移：优雅下线的三层放大

Day02 的 shutdownGracefully（停输入→等存量→超时兜底）放大到 10w 连接规模：

```
进程内：quietPeriod                → 集群内：摘注册/LB
停输入：不再接任务                 → 停新连：不再 accept
等存量：任务跑完                   → drain：客户端错峰重连（抖动 1~30s）
超时兜底：timeout                  → GracePeriod 覆盖 drain（K8s 默认 30s 是坑）
```

**同一模式在不同尺度复现**——识别模式并迁移，是"经验"和"资历"的区别。

## 五、面试叙事的工程学

### 5.1 钩子设计

2 分钟介绍刻意埋钩子（"有一次重连风暴的复盘比较完整"），把面试官引向准备最深的领域。**面试是对话的势能管理，不是知识的倾倒**。

### 5.2 反思题的备法

"重新设计会改什么"必须备真答案（鉴权预热/迁移自动化/双机房），展示边界感：知道系统的弱点和演进方向 = 真的做过；只有完美叙事 = 背的。

### 5.3 数字的位置

每段叙事至少一个数字（10w 连接 / P99 800ms / 30s 抖动窗口 / N+2），且能被追问到底层账本（每连接 10~50KB 的构成）。**数字是骨架，账本是肌肉**——Day01 差距1 在此闭环。

## 六、本日核心认知

1. **状态分离**：可丢（连接）与不可丢（会话）分居两层；无状态=状态死了能自动重建
2. **推拉结合**：推送是加速器，拉取是可靠性的地板——承认推送不可靠才是可靠性的起点
3. **按可丢性分级**：网关的智能在于"什么可以不推"
4. **可靠性三件套**：唯一标识+确认重试+对账补偿，IM/MQ/支付三域同构
5. **分布式删除必须校验归属**：路由清理的 gatewayId 比对 = 锁释放的持有者校验
6. **错峰是杠杆**：随机抖动把洪峰降 1/30；所有集体行为都要主动打散
7. **N+2 冗余**：容量=故障与发布并存时仍安全；规模化的第一收益是缩小爆炸半径
8. **连接迁移是优雅关闭的模式放大**：停输入→等存量→超时兜底，从线程到集群三层同构
9. **监控八指标**是"能不能 5 分钟发现事故"的分水岭（Day06 验证）
10. **面试叙事=数字骨架+账本肌肉+钩子管理**；反思题备真答案
