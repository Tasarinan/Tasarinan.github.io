## 一、实战日的方法论骨架：两条主线

Day05 四个场景收束成两条可迁移的方法论：

**主线一（性能类）：度量 → 定位 → 分层施策 → 收益翻译**

```
度量（/actuator/startup 画像，不猜）
  → 定位（三类大头；本次 76% 在 Bean 实例化、57% 在渠道串行建连）
  → 分层施策（外部连接 / 挂点 / 扫描 / 范围 / JVM——按收益风险排序落地）
  → 收益翻译（三笔账：窗口=兼容暴露面、回滚=两次窗口、探针=误杀防护）
```

与 JVM 周调优、Netty 周容量账完全同构——**性能治理的通用四步，变的只是度量工具与瓶颈形态**。启动治理的特殊性：瓶颈多在"启动即连远端的业务 Bean"而非框架本身——**Spring 不慢，是把远端等待穿在身上的人慢**。

**主线二（故障类）：报错定位 → 机制确认 → 为什么没拦住 → 防复发三防**

```
定位（生命周期是排查地图：断在哪一步，介入者就是嫌疑名单）
  → 机制确认（代理内存图/三级缓存时序——用第一性原理解释，不猜）
  → 为什么测试没拦住（单测无容器无代理；集成测试 mock 掉失败分支）
  → 防复发（静态扫描 ArchUnit / 真实容器测试 / review checklist 三防）
```

第四步是工程师与架构师的分水岭：**修 bug 是把错误代码改对，修"bug 进入生产的路径"是把检测体系补上**。

## 二、失效地图的工程化：从知识到系统

Day04 产出的四族失效地图，Day05 把它变成三道工程防线：

| 防线 | 形态 | 覆盖 |
|---|---|---|
| 静态防线 | ArchUnit 规则进 CI（循环依赖 slices / 自调用 / 有状态单例） | 编码期拦截 |
| 动态防线 | 真实容器集成测试 + 失败注入（扣减成功后续方失败必须回滚） | 测试期拦截 |
| 兜底防线 | 对账（库存流水 vs 订单状态）+ 周期审计（七项健康度） | 运行期发现 |

**"规则开始拦截"是知识变成系统的时刻**——ArchUnit 拦下第一个人写的循环依赖，比一百篇 wiki 都有效。这也回应了医疗周/支付周反复出现的主题：**人的纪律靠不住，检测体系才靠得住（纵深防御）**。

**七项健康度审计**（有状态单例/自调用/循环/连坐日志/切面耗时/启动趋势/Bean 数趋势）可以与 JVM 周的巡检清单、Netty 周的网关规约合并成**平台级 Spring 健康度规范**——面试时"我给团队建了这套"是高级工程师叙事，"这套体系拦下过什么"是架构师叙事（要积累案例数字）。

## 三、决策叙事：放弃全局 lazy 的架构判断

Day05 最值得回味的不是"做了什么"，是**决策与放弃**：

1. **核心链路服务放弃全局 lazy**——配置错误必须启动期暴露（fail-fast）；错误延迟到首请求 = 把故障从发布窗口挪到业务高峰，性质从"发布失败"恶化为"生产事故"
2. **依赖分级 fail-fast/降级启动**——医保结算通道连不上必须死；短信/报表通道异步重连（非核心依赖阻塞启动 = 可用性自伤）
3. **拆 Bean 优于自注入/AopContext**——多一个类不是代价，是"本该有的模块边界"的信号（设计债还清的标志）

三个决策共同的模式：**在"快"与"确定性"之间，核心链路永远选确定性**。启动提速的全部手段要过一道筛：**这个优化会不会把错误从"便宜的时点"（启动）挪到"昂贵的时点"（生产流量）？** 会的话，只在非核心路径用。

## 四、URL 全链路的收口价值：一张全栈挂图

四周热身题（TCP 握手挥手 → 可靠传输 → TLS → HTTP 演进）在 Day05 串成一条链——这条链的真正价值是**知识挂载结构**：

```
DNS（劫持/HTTPDNS）→ TCP（backlog/TIME_WAIT）→ TLS（0-RTT/PFS）→ HTTP（H2/H3/缓存）
  → LB/网关（限流/鉴权）→ DispatcherServlet → 代理链（事务/脱敏）→ 单例流水线
  → JVM（GC/Metaspace）→ MySQL（索引/事务）
```

**面试官从任意一段切入，都落在你某个往周专题的主场**——TCP/HTTP 八股不是孤立背诵，是全栈链路的粘合剂。这也是 CLAUDE.md 里"TCP/HTTP 八股穿插 Spring 周"路线的设计意图兑现：**八股为骨架知识供粘合，专题为八股供深度**。

**答法要领**：链路顺序 + 每步一句话机制 + 一个优化锚点，3 分钟收束——"性能优化=沿链路逐段找串行等待点"这句话本身就是一个方法论陈述（与"拆最深全局锁"同根）。

## 六、本日核心认知

1. **启动治理四步**：度量（startup 端点）→ 定位（三类大头，76% 在业务 Bean 的远端等待）→ 分层施策（五层）→ 三笔账翻译
2. **"Spring 不慢，慢的是穿在身上的远端等待"**——启动即连远端的 Bean 是主要矛盾
3. **核心链路放弃全局 lazy**：优化不能把错误从便宜时点（启动）挪到昂贵时点（生产流量）
4. **依赖分级 ADR**：结算通道 fail-fast、非核心异步重连——启动语义按依赖分级
5. **排查地图=生命周期**：三类启动报错按"断在哪一步"归位，介入者即嫌疑名单；/actuator/conditions 是条件装配的杀手锏
6. **事故闭环五段**：发现→机制（第一性原理确认）→为什么没拦住→数据修复→三防；后两段是架构师分水岭
7. **为什么测试没拦住**：单测无容器无代理、集成测试 mock 掉失败分支——真实容器+失败注入才算数
8. **失效地图工程化三防线**：ArchUnit 静态 / 真实容器测试 / 对账+周期审计——人的纪律靠不住，检测体系靠得住
9. **拆 Bean 是还清设计债的信号**：优于自注入/exposeProxy 的目标解
10. **URL 链路是全栈挂图**：四周热身题串成粘合剂——八股供骨架粘合，专题供深度
