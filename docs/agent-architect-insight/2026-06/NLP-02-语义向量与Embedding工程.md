# NLP-语义向量与Embedding工程

这篇是我基于项目实践与资料交叉阅读整理的学习笔记，目标不是复述概念，而是沉淀可直接复用的工程动作与判断标准。


Embedding工程的关键，不是“选一个榜单第一模型”，而是让语义表示、检索策略、评估体系协同工作。

## 一、向量化目标

向量化要解决的是“表达不同但语义相同”的匹配问题。关键词匹配解决不了改写、同义替换、跨句指代。

## 二、模型选型框架

选型建议按四个维度打分：
1. 语义区分能力（细粒度语义能否拉开）
2. 领域迁移能力（跨业务是否稳定）
3. 推理成本（向量生成延迟、存储、索引）
4. 维护复杂度（版本升级与重建成本）

避免只看通用基准总分，优先看与业务最接近的子任务。

## 三、相似度与检索策略

相似度不是只选余弦就结束，还要处理阈值和重排：
- 向量召回负责高召回
- 规则过滤负责高精度
- 重排模型负责最终排序质量

对于问答类场景，常见有效组合是 TopK召回 + 交叉重排 + 去冗余。

## 四、索引与更新

大规模场景需注意两件事：
1. 索引类型与维度匹配（高维密集向量需近似索引）
2. 增量更新机制（新增文档不能靠全量重建）

实践上要建立异步向量化队列，避免写入阻塞查询。

## 五、常见失败模式

1. 阈值固定不变，导致新场景召回断崖。
2. 只看平均指标，忽略长尾与硬样本。
3. 模型版本升级后未做历史向量兼容，线上结果漂移。

## 六、指标体系

推荐至少监控：
- Recall@K（召回）
- MRR/NDCG（排序）
- 噪声召回率（误召）
- 查询P95时延
- 向量更新延迟

## 七、实战案例

商品检索中，原系统只用余弦Top10，热门商品被重复召回。改造后：
1. 增加品类约束过滤。
2. 引入重排模型压制模板化描述。
3. 对低覆盖品类单独调阈值。

结果：Top10命中率提升，冷门品类曝光显著改善。

## 八、结论

Embedding工程是长期治理系统：表示学习、检索策略、评估回归必须一起做，单点优化难以持久。
## 学习者复盘

这轮整理里，我刻意保留了三类内容：
1. 真正会踩坑的决策点。
2. 可以落到监控面板的指标。
3. 能在下次项目里直接复用的流程模板。

后续继续学习时，我会优先补两块：
- 增加失败样本复盘（不仅保留成功路径）。
- 增加跨场景迁移对比（同方法在不同业务下的边界）。
