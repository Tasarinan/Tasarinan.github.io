# LLM-Prompt结构化与迭代方法

这篇是我基于项目实践与资料交叉阅读整理的学习笔记，目标不是复述概念，而是沉淀可直接复用的工程动作与判断标准。


Prompt工程的成熟标志，不是写出一条爆款提示词，而是建立持续迭代机制。

## 一、结构化Prompt模板

建议固定四段：
1. 任务定义
2. 输入约束
3. 输出格式
4. 失败处理（不确定时如何回应）

这样做的好处是：每次改动都知道改的是哪一段，便于回归。

## 二、迭代策略

采用单变量迭代：每轮只改一个因素（示例、约束、顺序、措辞之一），再做A/B评测。

常见有效动作：
- 少量高质量示例替代大量泛示例
- 用正向约束替代否定约束
- 增加自检步骤降低幻觉

## 三、输出控制

结构化输出（JSON或固定小节）可显著降低解析失败。对于关键任务要加格式校验和自动修复机制。

## 四、常见失败模式

1. 约束过多导致模型僵化。
2. 示例过长挤占事实输入空间。
3. 模板频繁改动却没有版本管理。

## 五、评估指标

- 格式通过率
- 任务完成率
- 幻觉率
- 同题一致性
- Prompt版本回归通过率

## 六、实战案例

在企业报销审单场景，原Prompt自由输出导致字段缺失。改为结构化模板 + 自检步骤后，字段完整率显著提升，人工返工率下降。

## 七、结论

Prompt工程本质是“输入接口工程”。有结构、有评测、有版本，才能长期稳定提升。
