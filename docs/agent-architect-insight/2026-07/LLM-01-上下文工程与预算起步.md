# LLM-上下文工程与预算起步

这篇是我基于项目实践与资料交叉阅读整理的学习笔记，目标不是复述概念，而是沉淀可直接复用的工程动作与判断标准。


LLM系统起步阶段最关键的不是模型多强，而是上下文和预算是否受控。上下文失控会直接引发成本、时延和质量三重问题。

## 一、起步阶段的核心问题

常见误区是“把更多内容塞进prompt就会更准”。实际中，信息噪声和窗口挤占会让质量反而下降。

## 二、上下文结构建议

建议固定四层结构：
1. 系统规则层（角色、边界）
2. 任务指令层（本轮目标）
3. 证据材料层（检索与事实）
4. 会话历史层（必要历史）

核心原则是“先结构化，再长度化”。

## 三、预算分档

起步就要定义预算档位：
- 快速档：低成本低时延
- 标准档：平衡质量与成本
- 深度档：高价值问题专用

请求先分档，再决定模型与上下文长度，避免默认高预算。

## 四、关键治理动作

1. 设单请求 token 上限。
2. 设会话累计上限。
3. 对超限请求自动降级。
4. 保存上下文组装日志，支持复盘。

## 五、常见失败

1. 历史对话无限累加。
2. 检索文档不做筛选直接注入。
3. 没有token监控，账单后知后觉。

## 六、建议指标

- 请求平均token与P95 token
- 有效token占比
- 超预算触发率
- 降级后可用率
- 响应P95时延

## 七、结论

上下文工程和预算治理必须同时起步。先把系统做稳，再追求更高上限，才能长期可持续。
