# LLM-RAG检索增强全链路

这篇是我基于项目实践与资料交叉阅读整理的学习笔记，目标不是复述概念，而是沉淀可直接复用的工程动作与判断标准。


RAG工程失败最多的原因，是把它当成“加个检索”而不是“完整证据系统”。

## 一、全链路拆解

RAG至少包含五段：
1. 数据入库
2. 分块与索引
3. 召回
4. 重排与上下文组装
5. 生成与引用

任何一段薄弱都会把错误传递到最终答案。

## 二、分块与索引策略

分块要兼顾两点：语义完整与检索粒度。过大块降低召回精度，过小块丢上下文。

建议按“结构边界优先、长度约束补充”策略执行。

## 三、召回与重排

召回负责广度，重排负责精度。常见有效组合：
- 向量召回找候选
- 规则过滤去噪
- 重排模型做最终排序

## 四、知识库治理

知识库必须版本化：新增、失效、冲突、回滚都要有记录。否则答案无法追溯，也无法做根因分析。

## 五、评测定位方法

至少维护三类测试集：
1. 事实命中集
2. 多跳推理集
3. 冲突信息集

异常时先查召回命中，再查重排，再查生成。

## 六、高频失败模式

1. 分块策略随意导致语义断裂。
2. 召回文档重复且冗余，浪费窗口。
3. 注入上下文无结构，模型抓不到证据主线。

## 七、结论

RAG的核心是“证据可控”，不是“答案流畅”。只要证据链可观测、可回放、可回归，可靠性就会持续提升。
## 学习者复盘

这轮整理里，我刻意保留了三类内容：
1. 真正会踩坑的决策点。
2. 可以落到监控面板的指标。
3. 能在下次项目里直接复用的流程模板。

后续继续学习时，我会优先补两块：
- 增加失败样本复盘（不仅保留成功路径）。
- 增加跨场景迁移对比（同方法在不同业务下的边界）。
