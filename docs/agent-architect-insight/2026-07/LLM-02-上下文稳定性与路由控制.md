# LLM-上下文稳定性与路由控制

这篇是我基于项目实践与资料交叉阅读整理的学习笔记，目标不是复述概念，而是沉淀可直接复用的工程动作与判断标准。


当场景增多后，系统主要矛盾从“会不会答”转为“是否稳定地答对”。稳定性问题多数来自上下文抖动和路由误配。

## 一、稳定性来源

同题不同答常见根因：
1. 上下文字段顺序不固定
2. 检索结果抖动
3. 路由策略漂移

## 二、上下文稳定化方法

- 固定模板槽位（目标、约束、证据、输出）
- 固定冲突裁决规则（来源优先级、时效优先级）
- 固定关键术语与字段命名

## 三、路由控制

建议按复杂度和风险分路由：
- 简单问题：短链路
- 中等问题：检索增强链路
- 复杂问题：多步推理+校验链路

路由必须可观测，且能回放。

## 四、高频失败模式

1. 多路由策略叠加后无主规则，命中混乱。
2. 子链路并发后输出冲突，缺少合并裁决。
3. 预算压缩过头，稳定性提升但质量退化。

## 五、评估方法

- 同题一致性得分
- 路由命中准确率
- 关键场景退化率
- 路由切换后的回归通过率

## 六、结论

上下文稳定性和路由控制是一体两面：一个保证输入确定性，一个保证执行确定性。两者一起做，系统才真正可运维。
