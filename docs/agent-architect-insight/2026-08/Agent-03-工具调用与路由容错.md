# Agent-工具调用与路由容错

这篇是我基于项目实践与资料交叉阅读整理的学习笔记，目标不是复述概念，而是沉淀可直接复用的工程动作与判断标准。


工具调用决定Agent可执行边界，容错机制决定Agent是否能在生产环境长期运行。

## 一、工具协议设计

工具定义必须包含：
1. 功能说明
2. 参数约束
3. 错误码语义
4. 超时与重试策略

缺一项都会增加误调用概率。

## 二、参数治理

参数治理核心是调用前校验：
- 类型校验
- 范围校验
- 业务规则校验

把脏参数拦在调用前，比调用后补救成本低得多。

## 三、路由与容错策略

常见容错组合：
1. 有界重试（限制次数）
2. 备用工具切换
3. 降级输出可解释结果

任何重试都必须带终止条件，防止无限循环。

## 四、可观测性要求

建议记录四类日志：
- 请求参数
- 工具响应
- 重试轨迹
- 最终裁决

缺少轨迹日志时，线上故障几乎无法复盘。

## 五、常见失败模式

1. 工具描述含糊，模型选错工具。
2. 参数默认值不合理，诱发隐性错误。
3. 容错策略过激，短故障放大成系统故障。

## 六、指标建议

- 工具调用成功率
- 参数校验拦截率
- 重试成功率
- 降级触发率
- 平均故障恢复时间

## 七、结论

工具调用能力是上限，容错能力是底线。上限和底线同时建设，Agent才可长期稳定交付。
## 学习者复盘

这轮整理里，我刻意保留了三类内容：
1. 真正会踩坑的决策点。
2. 可以落到监控面板的指标。
3. 能在下次项目里直接复用的流程模板。

后续继续学习时，我会优先补两块：
- 增加失败样本复盘（不仅保留成功路径）。
- 增加跨场景迁移对比（同方法在不同业务下的边界）。
