# Agent-任务规划与执行框架

这篇是我基于项目实践与资料交叉阅读整理的学习笔记，目标不是复述概念，而是沉淀可直接复用的工程动作与判断标准。


Agent系统能否稳定交付，关键在任务规划。没有规划的执行，通常只是随机试错。

## 一、规划目标

规划阶段必须明确：
1. 最终目标与验收标准
2. 约束条件（时间、权限、资源）
3. 失败时的回退策略

## 二、分层执行模型

推荐三层：
- 规划层：拆解目标、排序优先级、定义依赖
- 执行层：调用工具、生成中间产物、推进步骤
- 校验层：验收结果、检测冲突、触发回退

层间接口固定后，系统可维护性会明显提升。

## 三、状态建模

至少维护三类状态：
1. 任务状态（待办、进行中、完成、失败）
2. 工具状态（可用、降级、不可用）
3. 记忆状态（短期上下文、长期经验）

状态不可见时，重复执行和错误重试会激增。

## 四、执行闭环

建议闭环流程：
计划生成 -> 子任务执行 -> 结果校验 -> 失败重规划。

重规划不是重来，而是基于失败原因局部修正路径。

## 五、常见失败模式

1. 目标定义模糊，导致执行漂移。
2. 子任务依赖未声明，顺序错误。
3. 成功条件不清，系统无法判断结束。

## 六、建议指标

- 任务一次通过率
- 平均重规划次数
- 子任务超时率
- 任务完成时延P95
- 失败可恢复率

## 七、结论

任务规划框架的价值，在于把Agent从“能跑”提升为“稳跑”。先把规划做对，再谈能力扩展。
