## 题目一：一次前向在算什么

### 作答区

#### 1. 输出是词表上的分数，不是一句答案

自回归语言模型在位置 t 做的事可以压成三步：

```text
h_t = Transformer(token_1 ... token_t)     # 当前位置的隐状态
logits = W h_t                              # 长度 = 词表大小
p(next | 上文) = softmax(logits / T)        # T 是 temperature，默认 1
```

然后从 p 里取出一个 token，接到上文后面，再跑下一次。整句回答是这条链的副产品。模型没有一个单独的「提交答案」步骤。

因此：

1. 每个新 token 只能条件于已经写进上下文的东西：系统提示、用户问题、检索来的段落、模型自己刚才写下的字。
2. 权重在这次请求里不变。提示词、检索段落、工具结果改变的都是条件，不是参数。
3. 「知道」若指权重里的统计，「这次说出来」指的是条件分布被采样到了。两件事可以分开失败：权重里有，解码没走到；权重里没有，解码再怎么挑也走不出。

> 说法陷阱：「把温度调低，模型就更懂这个领域。」温度只改变 softmax 的锐度。领域事实若根本不在分布的高质量区域里，降低温度只会更稳定地输出那个错误的高概率 token。

#### 2. 注意力在这一步里的角色

当前位置的隐状态，是上文 token 的加权汇总再经前馈网络。解码器是单向的：位置 t 看不到 t 之后的 token。笔记里 Mixtral 的滑动窗口是在这个单向掩码上再加一刀，每个 token 只能看窗口内的过去，用 attention mask 实现。那是上下文能看见的范围，不是「理解力」的开关。

长上下文变差，常常是这一步的汇总变稀：关键证据在中间，权重被大量无关 token 摊薄。幻觉笔记里写的是开头和结尾更好、中间变差。这和「窗口号称 128K，所以整本书都被读懂了」不是同一句话。

#### 3. 提示词缓存复用的是前缀计算

`05_prompt_cache.md` 记的是厂商的提示词缓存：系统提示、长文档、工具说明这些稳定前缀，后续请求可以不重复计算。那篇解读里写缓存读取大约按输入价格的一成计费，费率以当时价目为准，机制不依赖这个数字。

缓存命中的条件是前缀字节级稳定。多一轮对话把前缀改掉，或者文档中间插了一段，缓存失效。它类似把重复前缀的 KV 留着，不把文档写进权重，也不让下一次换一个用户时仍然「记得」。

## 题目二：三个采样旋钮分别切在哪里

### 作答区

笔记对 temperature、top_p、early_stopping、repetition_penalty 的描述和实现不一致。下面按实现写。

#### 1. temperature：除的是 logits

```text
p_i = exp(logit_i / T) / Σ exp(logit_j / T)
```

| T | 分布变成什么样 |
|---|---|
| T = 1 | 不改模型交出的分布 |
| T < 1 | 高分 token 更突出，输出更稳，也更重复 |
| T → 0 | 接近每次取最大项，也就是贪心 |
| T > 1 | 分布更平，小概率 token 更容易被采到 |

笔记写「用高斯分布重新调整」。这里没有高斯采样。随机性来自按这个离散分布抽样，不来自另一个连续噪声分布。

#### 2. top_k：留下分数最高的 k 个，其余丢掉

在 softmax 之前或之后都可以做，效果是把尾部 token 的概率置零再归一化。k 小，候选少；k 等于词表大小，等于不截断。

#### 3. top_p：留下累积概率刚超过 p 的最小集合

按概率从高到低累加，取最小的那个集合使累积质量 ≥ p，其余丢弃，再归一化。这是 nucleus sampling。

笔记写「只选择前 p% 的词语」。p=0.9 不是「词表里排名前 90% 的词」——那会留下成千上万个 token。0.9 指的是概率质量。分布很尖时，一两个 token 就凑满 0.9；分布很平时，集合才会变大。

#### 4. 三个旋钮的顺序

常见顺序是：

```text
logits
  → 重复惩罚等改 logits
  → 除以 temperature
  → top_k / top_p 截断并重新归一化
  → 抽样或取 argmax
```

截断发生在温度之后时，温度会改变谁进得了 nucleus。所以「先固定 top_p 再扫温度」和「先固定温度再扫 top_p」不是同一组实验。

## 题目三：贪心、采样、beam 各选了一条什么路径

### 作答区

#### 1. 三种策略

| 策略 | 配置上的样子 | 每一步在做什么 | 它优化的东西 |
|---|---|---|---|
| 贪心 | `do_sample=false`，`num_beams=1` | 取当前概率最大的 token | 每步局部最大 |
| 采样 | `do_sample=true`，可加温度和 top_p | 按分布随机取一个 | 多样性，路径不唯一 |
| beam | `num_beams>1`，通常不采样 | 保留若干条部分序列，按累积分数扩展 | 序列分数，不是单步最大 |

贪心可以在某一步锁死：一个高概率的错误 token 一旦写下，后面的条件全变了。beam 保留多条候选，仍可能全体共享同一个早期错误。采样让同一提示走出不同句子，那些句子可以都是错的，只是错法不同。

笔记把 `num_beam_groups` 写成「并行所以更快」。分组束搜索是 diverse beam search：组间加多样性惩罚，用来要多条不一样的结果。它增加的是搜索开销，不是免费加速。

#### 2. early_stopping 管的是 beam 何时收束

Hugging Face 里 `early_stopping=True` 的含义是：已经有 `num_beams` 条完成的假设（遇到 EOS）就可以停。它不负责「看见句号、问号就裁剪」。句子结束靠的是 EOS，或调用方自己的停止符。笔记把这两件事写成了一件。

`max_length` 是 token 数上限，含提示还是只含生成，以具体实现的参数为准（有的接口用 `max_new_tokens` 只限制新生成的长度）。它不是「句子的语义完整」。

#### 3. 惩罚项改的是分数，不是事实

| 参数 | 作用在哪 | 核对后的行为 | 笔记里需要改的句子 |
|---|---|---|---|
| repetition_penalty | 已出现 token 的 logits | 1.0 是恒等。大于 1 时，正 logit 除以惩罚、负 logit 乘以惩罚，用来压重复 | 「取 0 表示不惩罚」不成立 |
| no_repeat_ngram_size | 候选 token | 禁止当前输入里已经出现过的 n-gram 再次出现，提示和已生成部分都算。设为 3 就是任意连续 3 个 token 不得再出现 | 笔记只写成「和原始文本比对」，范围含糊 |
| length_penalty | beam 的序列分 | 序列对数分（负数）除以 `长度 ** length_penalty`。惩罚越大，长序列的负分越接近 0，排序越偏向长序列；小于 0 则偏向短序列。默认 1.0 | 它不是采样路径上的独立创造力旋钮 |
| bad_words_ids / suppress_tokens | 候选 token | 这些 id 不会被选中 | 这项是禁词，不是事实核查 |

`typical_p` 是 locally typical sampling：留信息量接近期望的 token，不是「为了把句子写长」。`epsilon_cutoff` 丢掉概率低于阈值的 token。`eta_cutoff` 是随分布熵变化的截断，不是「当前序列和次高概率的比值，小于就停止生成」。

#### 4. 这些旋钮共同的边界

解码可以让输出更短、更少重复、更贴某个格式、更多样。它不能：

1. 把训练截止日之后的事情补进权重。
2. 把检索没召回的段落补进上下文。
3. 把已经写错的前提从后文里擦掉。后文只会条件于那个错 token，这就是 Day02 的滚雪球。

格式约束（JSON、禁词、强制包含某个 token）是解码或后处理能做的。事实约束要有证据进入上下文，或有运行时去查。

## 本日能力差距与补足方向

### 差距1：说不清一次前向的产出

- **现状**：用「理解了提示词」描述生成。说不出 logits、softmax、把 token 接回去再前向。
- **核对后的水平**：画出「条件 → 词表分布 → 一个 token → 新条件」的环，并指出权重在环里不变。
- **补足方向**：对一个 10 token 的回答，口头走两步，说明第二步的输入比第一步多了什么。

### 差距2：参数说明和实现不一致

- **现状**：沿用笔记里的高斯温度、前 p% 词表、句号早停、惩罚为 0。
- **核对后的水平**：每个参数能归到 logits、候选集合、序列分三类之一。
- **补足方向**：把本题对照表放在改生成配置的旁边。遇到新参数，先找它乘在哪一项上。

### 差距3：用多样性代替证据

- **现状**：答错就加温度或加 beam，不检查上下文里有没有证据。
- **核对后的水平**：先区分「分布里有正确 token 但没采到」和「正确 token 概率本来就低」。只有前一种适合动解码。
- **补足方向**：同一提示固定种子扫温度。若所有温度都走向同一个错误事实，停止调解码，转到 Day02 和 Day03。
