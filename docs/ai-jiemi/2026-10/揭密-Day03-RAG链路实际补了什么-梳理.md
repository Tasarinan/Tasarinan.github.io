## 一、RAG 是一次上下文装配

初级说法是「模型学会了知识库」。装配过程里模型的权重不动。动的是送进 Day01 那个条件分布的 token。

| 阶段 | 产出 | 失败时回答会变成什么样 |
|---|---|---|
| 解析 | 带结构的文本 | 库里查询永远缺那一页 |
| 切块 | 可独立使用的片段 | 召回半句，模型把另一半编完 |
| 索引 | 稀疏向量或稠密向量 | 同义找不到，或原词找不到 |
| 查询 | 一条自洽的检索语句 | 「门票」找不到「颐和园」 |
| 拼接 | 短、靠前、角色分明的证据 | 证据在中间，或和指令搅在一起 |
| 生成 | 条件于这些 token 的续写 | 证据错了就顺着错证据写 |

**关键洞察：检索质量的上限在金段落实验里已经显形。** 人工把对的段落放进去仍答错，问题在阅读和生成；金段落明显好于检索结果，问题在召回。两条路的修补不共用一套参数。

## 二、分数、词法、假设文档，是三种不同的证据观

```text
BM25     证据 = 罕见词在文档里出现
向量     证据 = 嵌入空间里邻近
HyDE     证据 = 先想象一篇文档，再按想象去邻近
```

三种观可以并联，不能互相解释。原词命中失败时加大嵌入维度，解决不了编号和专名；抽象问法失败时只加 BM25，仍然对不上文档里的具体说法。HyDE 在第三种观上多一次生成，想象错了，前两种索引都会被错查询使用。

混合检索之后还有一件单独的事：两路分数不在一个刻度上。不能把 BM25 的 12 分和余弦 0.8 加权平均之后假装得到一个概率。

## 三、架构表是动作表

八种名字容易被当成成熟度阶梯：从 Naive 走到 Agentic 就是升级。阶梯不存在。每上一级只增加一个可观察动作，并带来这个动作自己的失败。

选型句子应该是：

1. 坏样本是问法抽象，才考虑假设文档。
2. 坏样本是来源过时，才考虑在送给模型之前对另一来源做核对。
3. 坏样本是关系而不是段落相似，才考虑图。
4. 坏样本是一次查询写不对，才考虑多步循环。
5. 坏样本是简单事实，停在朴素检索加过滤。

**和 Day02 的接口**：信息不足、错误材料、干扰、位置、曲解，分别对应查询改写、来源核对、过滤、把证据摆短摆前、以及「金段落仍答错就不要再加检索层」。

## 四、长上下文和 RAG 比的是证据的位置，不只是产品形态

NEPA 笔记的四格把「有没有证据」和「证据怎么放」拆开了。全文很长却不如短的检索段，说明长度不是阅读的单位。位置效应（两头好于中间）给这件事一个生成侧的解释：无关 token 稀释了注意力，关键证据没有成为高权重条件。

因此「上下文已经 128K，可以不下检索」要先过四格里的两格：全文对照人工指定段落。全文接近金段落，检索的收益变小；全文明显差，检索的收益是把段落搬位置，不是把模型换聪明。

## 五、本日核心认知

1. **RAG 装配上下文。** 权重留在 Day07 的微调里再谈。
2. **入库前的解析和切块决定检索的天花板。** 自动问答对会把生成错误写进库。
3. **相关分是序，不是概率。** 阈值要自己校准。
4. **多轮问题先改写成自洽查询。** 改写要留痕。
5. **BM25、向量、HyDE 是三种证据观。** 按失败类型选，不按时髦程度叠。
6. **八种架构每种只多一个动作。** 动作对不上坏样本就不要上。
7. **长上下文实验要带四格条件。** 金段落用来区分「没检索到」和「检索到了也不会读」。
