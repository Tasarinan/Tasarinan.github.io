## 背景

`34_Prompt工程/01_方法汇总/01_使用指南.md` 把提示词写成一套可迭代的写法：指令和数据用分隔符分开、指定输出格式、少样本固定文风、让模型先自己做一遍再评判别人的答案、用思维链把步骤写出来。`02_26种prompt套路.md` 则把这些和「我会给你小费」「你将受到惩罚」「用肯定句不用否定句」放在同一张清单里，并说某些条目对大模型更明显、其中「先向用户追问直到信息够了」在 7B 到大模型上都有提升。`10_ReAct.md` 在提示词上加了 Action，动作空间是搜索和查找。

今天把清单拆开：哪些句子真的改变了下一步的条件，哪些句子只是在推理时没有对应机制的措辞。

## 题目一：提示词不写权重，它写条件

### 作答区

#### 1. 一条提示词生效时，发生的事

Day01 的分布是 `p(next | 上文)`。提示词是上文的一部分。它生效，意味着某些 token 的条件概率变了。它不生效，意味着那几个字没有把概率质量移到你要的路径上。

所以迭代提示词的检查方式笔记已经写了：看输出，反查是哪一段条件没起作用。不看提示词「是否更专业」。

#### 2. 能对上机制的写法

| 写法 | 条件发生了什么变化 | 笔记里的例子 |
|---|---|---|
| 分隔符 | 指令 token 和数据 token 不再混成一段，模型较不容易把数据里的句子当成新指令 | 三个反引号包住待摘要文本 |
| 输出骨架 | 后文必须接在给定的键或步骤编号后面，路径被钉住 | JSON 的键；Step 1…Step N；不符合就写固定的一句 |
| 少样本 | 文风和标签的对应出现在上下文里，下一步分布向样例靠拢 | 孩子问、长辈用比喻答，下一问延续同一种声音 |
| 先独立作答再比较 | 避免学生的错误答案先进入条件，把评判步骤锁在那条错误附近 | 先写自己的解，再判断学生解是否相同 |
| 步骤写进上下文 | 中间结论变成后续 token 的条件，相当于把一次长跳拆成几次短跳 | 先摘要，再翻译，再数名字，再出 JSON |
| 输出引导 | 回答的开头几个 token 由你给定，后面只能顺着这个开头写 | 在提示结尾放上预期回答的起句 |

这六类的共同点是：你能指出多出来的 token 是什么，以及它们位于生成之前还是生成之中。

「先自己算再打分」对得上滚雪球。学生的错解如果先出现，后面的「正确/错误」会条件于那段错解。把模型自己的解写在比较之前，是在调整条件的顺序。

#### 3. 对不上机制的写法

26 条里还有一类：我会给你奖励、你将受到惩罚、不要有偏见、像人一样自然。推理时没有一个奖励信号去乘 logits，也没有一个惩罚项对应「小费」这两个字。它们若改变输出，只是因为相似句子在训练分布里和某种文风一起出现过。

这种改变不稳定，而且换一个模型就要重测。笔记自己的效果比较也不是「26 条全部同等有效」：它写某些条目对大模型更明显，追问直到信息足够那一条在小模型上也被观察到提升。即使如此，比较仍然依赖当时的模型和题目。能留下来的做法是：把「先追问」写成对话状态机——信息不足时下一步只允许提问——而不是指望一句「你必须问我」在所有模型上成为约束。

否定句（「不要做某事」）的弱效应也来自条件：被禁止的内容往往要先被写进上下文，下一步分布反而看见了它。能改成肯定的输出骨架时，就不要用否定句去描述你不想见的 token。

> 说法陷阱：「把提示词写长，模型就更遵守。」使用指南里的原句是：清楚不等于短，长提示可以因为更明确而更好。长度本身不是杠杆。长在指令和数据搅在一起时，就是 Day02 的干扰和位置问题。

## 题目二：思维链改变的是路径，不是知识

### 作答区

「一步步思考」若起作用，是因为模型先生成中间句，这些句子成为后续 token 的条件。中间句写对了，最后一步的条件更好；中间句写错了，Day02 的滚雪球照样发生，而且更长。

因此思维链有两个验收点：

1. 中间步是否可核对。算术、引用原文、抽出的实体，可以和输入对上。
2. 最后答案是否真的用了中间步。有的生成先写答案再补一段看起来像推理的文字，那一段是事后的条件，不是推理过程。

笔记把思维链和少样本合在一起用：样例里就演示「先写步骤再写结论」。这比只加四个字「请逐步思考」更明确，因为样例把路径的形状放进了上下文。

思维链不创造截止日之后的事实，也不代替检索。步骤里写出的数字若没有来源，只是一条更长的无证据路径。

## 题目三：ReAct 的动作发生在模型外面

### 作答区

#### 1. 循环的三次交接

ReAct 笔记的例子是 HotpotQA 式的多跳：要回答遥控器最早控制什么软件，模型交替产生想法、动作和观察。

```text
Thought   模型生成的文本。计划下一步查什么
Action    模型生成的文本。例如 Search[Apple 遥控器]
          —— 到这里模型的工作暂停
Observation  运行时执行搜索，把结果写回上下文
Thought   模型看见观察之后再生成
```

动作空间在那篇论文设定里是 `search[entity]` 和 `lookup[string]`，外加结束。模型不会执行搜索。它只产生运行时能解析的字符串。解析失败、搜索为空、观察文案把模型带向错误实体，都是这条循环的正常失败，不是模型「拒绝使用工具」。

笔记里的轨迹已经演示了空观察：搜 Front Row 没有结果，下一步才改查询。空结果必须写回上下文。若运行时把空结果吞掉，模型会条件于一个不存在的成功。

#### 2. 和普通提示词的差别

普通提示词在生成开始前把条件放齐。ReAct 在生成之中多次停下来，让模型外面的程序改条件，再继续。差别是停不停、谁来改条件，不是模型内部多了一个行动器官。

所以排障分三行记：

| 行 | 看什么 | 坏了的样子 |
|---|---|---|
| Thought | 计划是否指向能执行的查询 | 计划在重复同一句，或查询缺少上一步的实体 |
| Action | 文本能否被解析成已注册的动作 | 编了一个不存在的工具名或参数 |
| Observation | 写回的内容是否就是工具的结果 | 空结果被写成「已找到」，或截断丢了实体 |

#### 3. 框架把这个循环藏起来之后

Agent 笔记里的 ReAct 机制篇写了一句站得住的话：编排框架把循环包起来之后，人们会以为智能体自己在行动。要优化和排障，仍要把 Thought、Action、Observation 打出来。看不到这三行，就无法知道是想错、调用错，还是观察错。

Function Calling 是这件事的一个接口形态，Day05 再展开：模型输出结构化参数，运行时执行，结果再写回。预训练把格式做进权重，只说明较少依赖提示词来教格式，不说明模型开始自己发 HTTP 请求。

## 本日能力差距与补足方向

### 差距1：清单条目没有作用点

- **现状**：分隔符、小费、惩罚、思维链同等对待，效果不好就整表重试。
- **核对后的水平**：每条提示词能归到「改变哪段条件」或「只是训练里的措辞」。
- **补足方向**：改提示词时只改一类条件，看输出里对应的 token 变了没有。

### 差距2：思维链只看最后一句

- **现状**：加了「逐步思考」就认为推理发生了。
- **核对后的水平**：核对中间步，并确认最终答案条件于这些步骤，而不是先答后补。
- **补足方向**：把中间步和输入对一下。对不上就停在这一步，不继续加代理。

### 差距3：Action 被看成模型的行为

- **现状**：轨迹里出现 Search 就说模型会搜索。
- **核对后的水平**：画出暂停点：Action 之后必须由运行时执行，Observation 必须原样写回。
- **补足方向**：故意返回空观察，看下一步是否改查询。不改，循环就没有用上观察。
