> 出题日：Day03 - RAG 链路

## 背景

`35_RAG/02_原理介绍/01_原理.md` 把流程写成：加载文档、切块、做向量索引、按问题检索、把问题和片段一起送进模型。`02_微调vsRAG.md` 用「逐 token 的概率生成」解释为什么会有流畅的错话，又把 RAG 和微调画成两条补救。`03_设计模式.md` 列出八种架构。`03_RAG_vs_long_context.md` 用一份环境评估文档的对照，比较「不给上下文、给全文、给检索段、给出题用的金段落」。BM25 笔记则把词法检索说成「按罕见词找文档的门外汉」。

这些笔记里站得住的部分是同一句：RAG 把外部文本放进这一次的条件。它不把文档写进权重。今天把这句话落到每一步会坏在哪里，以及八种架构各自多出来的那一个动作。

## 题目一：五步链路，每步的产出和失败

### 作答区

#### 1. 链路实际交出什么

```text
文档 → 纯文本 → 片段 → 向量或稀疏索引
                         ↓
问题（可能先改写）→ 若干片段 → 拼进本次提示 → 模型按 Day01 的方式继续生成
```

模型侧没有新的算子。新的是提示里多出来的那些 token。Day02 检索层的五条失败，全部发生在「片段变成 token」之后。

#### 2. 解析：进索引之前就已经丢了

笔记写得很直接：TXT、Word、PDF、HTML、表格要先变成文本。LangChain 一类加载器覆盖了格式，复杂 PDF 仍然会丢段落、丢表、丢阅读顺序。这一步的失败在索引里看不到，只会在回答里表现为「文档里有，检索永远找不到」。

验收看的是：抽出来的文本是否还保留标题、段落和表头。不看嵌入模型的榜单。

#### 3. 切块：语义完整是这条链路的第一约束

按长度或按句号切开，会在四种情况下把证据拆碎：PDF 没有段落、答案跨很长的原文、作者换行不规则、表格被按行撕开。

笔记给出的三种补法，本质都是「让一个片段独自就能答题」：

| 补法 | 多出来的产物 | 代价 |
|---|---|---|
| 用模型判断边界 | 更接近段落的块 | 切分成本 |
| 先摘要再索引 | 短文本，语义被压缩进摘要 | 细节被摘要丢掉 |
| 用模型先做成问答对 | 把远处的信息收进一个短问答 | 问答对本身会带上生成错误 |

第三种已经引入了一次生成。问答对若是错的，索引会把错误变成可检索的「证据」。这是 Day02 的「接受错误材料」，发生在入库时。

#### 4. 检索分不能直接当概率阈值

只取 TopK 再拼接，K 条里必有无关片段。笔记建议按相关分过滤，并要求向量归一化，这样内积落在固定区间。

另一句更关键：排序模型常用配对训练，评价指标是 AUC、NDCG 这种序。A>B>C 在分数 `[0.1, 0.2, 0.3]` 和 `[0.7, 0.8, 0.9]` 上是一样的。序对了，阈值仍然没法从 0.8 读出「80% 相关」。要阈值，就要在自己的标注上做校准，而不是借用别的任务的 0.8。

#### 5. 多轮查询会丢掉指代

笔记里的例子：上一句问「颐和园在哪里」，下一句问「门票多少钱」。只用后一句去检索，索引不知道是哪里的门票。

两条补法都是在检索前改写查询，不是在生成后打补丁：

1. 判断当前句是否依赖上文，依赖就把查询串起来。
2. 让模型根据最近几轮改写出一条自洽的检索查询。

第二种改写本身是一次生成，可能改错实体。改写结果要和原问题一起留下，否则排障时分不清是检索错了还是改写错了。

#### 6. 拼进提示词时，格式是训练分布的一部分

笔记给了一段把证据、历史、问题塞进 XML 标签的提示，并写明：这在强模型上像一个基线，在 6B、13B 上不稳定。原因按笔记的说法，是这些模型的后期训练更熟悉对话角色，而不是一大段混在一起的指令。

把同一份证据改成 system 里放规则和证据、历史按 user/assistant 交替、最后一条才是当前问题，是在把条件变成模型见过的形状。这仍然不增加证据，只减少「证据在上下文里但没被当成证据读」的概率。

礼貌拒答也被笔记放在这一步：没把握时按人设拒答，主要靠提示词，上限仍受模型能力约束。拒答文案写进提示，只是增加那条路径的概率，见 Day02。

## 题目二：词法检索和向量检索回答的是不同的问题

### 作答区

#### 1. BM25 在数什么

BM25 笔记的机制可以收成三步：

1. 对文档集分词，词表维度就是稀疏向量维度。
2. IDF：词在文档集合里越少见，权重越高。「的、是、了」压下去，专名抬上去。
3. TF：这个词在当前文档里出现越多，这份文档越靠前。实际公式里 TF 有饱和，避免一个词刷屏；再按文档长度做归一，避免长文档只因为词多而占优。

BM25 回答的是「查询里的罕见词是否出现在这篇文档里」。它不回答「这句话在说同一件事吗」。改了一个同义词，词法分会掉下去。

#### 2. 向量检索回答邻近，不回答真值

嵌入把文本压成稠密向量，用内积或余弦找邻近。邻近表示训练目标下的语义接近，不表示事实成立，也不表示分数可当概率。

两边一起用的理由就这一句：专名、编号、原词命中靠 BM25；换一种说法仍能找回来靠向量。只留一边，就会系统性错过另一类查询。

#### 3. HyDE 多了一次生成

设计模式笔记里的 HyDE：问题和文档在字面上并不接近，于是先让模型写一篇假设文档，再用假设文档的向量去检索。

多出来的动作是一次无证据生成。假设文档若写错实体，检索会被错误实体带走。HyDE 适合「问法抽象、文档措辞具体」的失败样本，不适合「实体必须原词命中」的失败样本。后者应先走 BM25。

## 题目三：八种模式各自多哪一个动作

### 作答区

`03_设计模式.md` 的名单，按「相对朴素 RAG 多出来的那一步」重写。多出来的步如果对不上你手头的坏样本，这一层就是空转。

| 模式 | 多出来的动作 | 对得上的坏样本 | 新引入的失败 |
|---|---|---|---|
| Naive | 查询向量对文档向量取邻近 | 问和文档措辞接近的事实题 | TopK 里的无关片段、分数当阈值 |
| Multimodal | 跨模态嵌入，文本去碰图像等 | 证据不在纯文本里 | 解析和嵌入都要重做 |
| HyDE | 先生成假设文档再检索 | 问法抽象、文档很具体 | 假设文档写错会带偏检索 |
| Corrective | 用可信来源核对检索结果，再决定是否送给模型 | 库内文档过时或不可信 | 核对源本身要被定义，否则只是又一次检索 |
| Graph | 抽成实体关系再检索 | 问题问的是关系而不是段落相似 | 抽图那一步会抽错关系 |
| Hybrid | 稠密检索和图或词法一起走 | 既有原词又有关系 | 两路分数不能直接比大小 |
| Adaptive | 先判断要不要拆成子问题、要不要多跳 | 简单题被复杂流程拖垮，或复杂题被单次 TopK 漏掉 | 分类器判错则整条路径错 |
| Agentic | 用带规划的循环多次检索、调工具 | 一次检索的查询写不对，需要根据观察再查 | 每一步观察都可能滚雪球，见 Day05 |

笔记把 Agentic RAG 说成「最适合复杂工作流」。复杂度本身不是入选理由。入选理由是：坏样本显示一次检索的查询不够，而且运行时能够执行下一步动作并把观察写回。

## 题目四：长上下文对照实际比的是什么

### 作答区

`03_RAG_vs_long_context.md` 摘的是 NEPA 环境文档上的一组实验，模型包括 Claude Sonnet、Gemini、GPT-4。问题由 GPT-4 按选定段落生成，再用 RAGAs 看事实重叠和语义接近。题型分十类，从封闭是非到发散、求解。

四组条件才是这篇笔记里可核对的部分：

| 条件 | 模型看见什么 | 这组在测什么 |
|---|---|---|
| None | 只有问题 | 参数知识够不够 |
| Complete PDF | 整份文档 | 长上下文里能不能自己找到证据 |
| Silver | 检索回来的段落，含噪声 | 真实检索管道 |
| Gold | 出题时用的那段原文 | 证据已经放对位置时的上限 |

笔记转述的结果是：在这组文档和模型上，检索段落优于把整份 PDF 塞进去，也优于不给上下文；封闭题好于发散题和求解题。金段落那一组的意义是上限：若金段落明显好于银段落，缺口在检索命中，不在「再换一个更会读长文的模型」就能自动补上。

这组结果不能写成「RAG 永远优于长上下文」。它依赖文档形态、检索器、模型和题型。换一套材料要重跑这四格，而不是引用结论句。

和 Day02 的位置效应合在一起看：全文条件变差，可能就是关键段落到了长文中间。检索的价值常常是把那段挪到提示里靠前、靠短的位置，不是发现了新的智能。

## 本日能力差距与补足方向

### 差距1：只会画一条从文档到回答的箭头

- **现状**：五步都叫 RAG，坏了不知道断在解析、切块、查询、分数还是拼接。
- **核对后的水平**：每步说出产出物和一种失败形态。
- **补足方向**：用「门票多少钱」这种省略指代的追问，强制露出查询改写；用一份双栏 PDF 露出解析。

### 差距2：0.8 被当成相关概率

- **现状**：向量分低于 0.8 就丢弃，换一个嵌入模型之后阈值原样搬过去。
- **核对后的水平**：阈值来自自己的标注校准。排序指标不提供阈值。
- **补足方向**：抽 50 对相关 / 不相关，看分数分布是否分开。分不开就不要用固定阈值。

### 差距3：架构名单代替坏样本

- **现状**：八种模式都想上。
- **核对后的水平**：先有坏样本，再选择多出来的那一个动作。
- **补足方向**：本题的表。新增一种模式时先写「多出来的动作」和「新引入的失败」。

### 差距4：一篇论文的结论句被拿去选型

- **现状**：用 NEPA 实验证明所有长文档都应该改成 RAG。
- **核对后的水平**：记住四格对照。金段落和银段落的差距指向检索，全文和金段落的差距指向「放进上下文的方式」。
- **补足方向**：自己的文档至少做 None / 全文 / 当前检索 / 人工指定段落这四格里的两格，再决定。

## 附录：本日关键认知速查

| 认知点 | 关键结论 |
|---|---|
| RAG 改变的对象 | 这次提示里的 token，不是权重 |
| 解析 | 复杂 PDF 会在入库前丢掉结构和表 |
| 切块 | 片段要能独立答题；自动问答对会把生成错误写进索引 |
| 阈值 | 排序分不是概率，要在自己的数据上校准 |
| 多轮 | 检索前改写查询，否则省略指代找不到文档 |
| 提示形状 | 6B/13B 上，对话角色比一大段混合指令更接近训练分布 |
| BM25 | 罕见词是否出现；同义改写会失手 |
| 向量 | 语义邻近；不管事实真伪 |
| HyDE | 多一次无证据生成，会把检索带向假实体 |
| 八种模式 | 每种只多一个动作，动作必须对上坏样本 |
| 长上下文实验 | 四格对照，结论限于那组文档、模型和题型 |
| 金段落 | 上限在证据是否放对，不在模型突然会读 |
