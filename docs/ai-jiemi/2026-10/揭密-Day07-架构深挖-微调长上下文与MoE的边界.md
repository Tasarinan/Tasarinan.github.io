## 一、今日主题

Day01 到 Day06 把单次回答拆成条件、路径和运行时。还有三个说法经常冒充成「把模型本身变强」：微调、把文档全部放进长上下文、换一个 MoE。材料在 `35_RAG/02_原理介绍/02_微调vsRAG.md`、`31_LLM/05_训练/07_微调/01_概述.md`、`05_训练/10_MOE/02_mixtral_moe_原理和代码.md`，以及 Day03 已经用过的长上下文对照。

三个说法各改一笔不同的账。混用时，Day06 的链路会被错误的层再走一遍。

```text
微调        改权重。生效在之后的请求里，范围是训练说法的邻域
长上下文    改这一次能放进条件的 token 上限。不保证中间的证据被用到
MoE         改每个 token 激活哪些前馈专家。计算量看激活参数，显存看要装下的专家
```

## 二、微调改权重，而且只在邻域里稳

### 1. 「没有专业知识」这句过满了

微调对比笔记列了大模型的局限：逐 token 所以会说得很顺但说错、私有和实时事实不在参数里、具体事实记不稳、训练周期赶不上时效、企业数据不能直接送上公网、没有感知、没有用户模型。

这些局限里，站得住的是边界：参数记忆有截止日，记具体事实不稳定，私有数据不在权重里。过满的是「不具备专业知识」。公开领域的语言和一部分事实已经在预训练里。RAG 补的是这次能摆上桌的证据，不是把一张空白的模型第一次教会说话。

### 2. 三种改法不在一个层

| 做法 | 改哪里 | 笔记里的边界 |
|---|---|---|
| 提示词 | 本次条件 | 不改参数，换说法就要重新看输出 |
| 连续提示（P-Tuning） | 插入可训练的连续向量，主干冻结 | 优化的是连续提示，不是把一段自然语言写进词表就能达到最优 |
| 微调 / LoRA / QLoRA | 权重或低秩适配器 | 输入离开训练说法时，会退回原来的生成 |

概述笔记开头的失效要单独记住：对话微调之后，测试说法和训练说法差得远，模型不按训练集的回答走，而用原来的能力回答，输出变得不可控。作者认为小样本时更有效的是人工补释义，让邻域里多几种说法。这说明微调学到的是见过的条件邻域，不是一个抽象技能自动覆盖所有改写。

P-Tuning 的要点是：离散提示词从优化角度看不一定是最好的条件，所以用连续向量代替，主干可以冻结。它仍然是「在冻结模型旁边加一小段可训练条件」，不是检索，也不是把知识库背进主干。

### 3. QLoRA 省的是显存，99.3% 是一次特定打分

概述笔记对 QLoRA 的机制记录是四件：

| 做法 | 在省什么或补什么 |
|---|---|
| 4-bit NormalFloat | 用一种 4-bit 数据类型装权重 |
| 双重量化 | 再压量化常数，笔记写 65B 大约省 3GB |
| 分页优化器 | 用统一内存避开长序列小批量时的优化器峰值 |
| 所有线性层都加 adapter | 用更多可训练参数补 4-bit 带来的损失；常见 LoRA 只加在 query 和 value 上 |

「Guanaco-65B 达到 ChatGPT 的 99.3%」是这篇笔记转述的、用 GPT-4 在 OASST1 相关评测上的分数。它不是两个系统在所有任务上的比值。同一节更可核对的对比是：数据从 5 万增加到 15 万，指标不明显上升；换一套数据，指标差一截。条数不是第一杠杆，数据是否覆盖你要的说法才是。

微调因此不能替代 Day03。票价、内部制度、昨天的变更，仍应作为证据进入条件。微调适合把稳定的格式、口吻、工具调用格式推进权重，并接受邻域之外会退回。

## 三、长上下文改的是容量，不是注意力的均匀度

Day03 的四格已经规定了怎么说这件事。这里只补它和微调的分界。

| 你想要的效果 | 长上下文能做的 | 它不做的 |
|---|---|---|
| 这次把更多原文放进条件 | 提高放得下的 token 上限 | 保证中间段落的权重 |
| 少建一个索引 | 在全文条件接近金段落时，可以不检索 | 在全文条件明显差于金段落时，自动找到那一段 |
| 记住以后每次都这么答 | 不做。下次不贴文档就回到参数知识 | 把文档写进权重是微调或继续预训练的事 |

位置效应和 NEPA 全文条件一起看：窗口变大，无关 token 可以变得更多，关键证据更容易落到中间。容量增加有时会制造 Day02 的那一种失败，而不是消除它。

提示词缓存和长上下文是两笔账。缓存复用稳定前缀的计算；窗口决定前缀加文档能不能放下。缓存命中不提高中间证据的利用率。

## 四、MoE 改的是每个 token 走哪条前馈

### 1. 8×7B 不是八个模型一起回答

Mixtral 笔记里的数字：总参数约 46.7B，每个 token 激活约 12.9B。不是 8×7=56B。差出来的部分是因为注意力和嵌入共享，专家复制的是前馈块，不是整个模型。

每个 token 的路径：

```text
router_logits = Linear(hidden)          # 每个专家一个分
weights = softmax(router_logits)
取 top-k（Mixtral 是 2），再对这 k 个分重新归一化
输出 = Σ 选中专家的 SwiGLU 前馈(hidden) × 对应权重
```

专家本身是带门控的前馈：`w2( silu(w1(x)) * w3(x) )`，和 Llama 一类的 SwiGLU 相同，只是这样的块有 8 份，每次用 2 份。

路由是一次线性层加 softmax 加 top-k。它不是一次规划，也不是 Day05 的代理选择。选错专家的后果是这个 token 的前馈算子不同，不会自动触发检索或工具。

### 2. 三笔账分开报

| 账 | Mixtral 笔记中的量级 | 选型时的含义 |
|---|---|---|
| 总参数 | 约 46.7B | 要下载和存放的权重大小 |
| 激活参数 | 约 12.9B / token | 计算量更接近这个量级，而不是 46.7B |
| 常驻显存 | 会用到的专家都要在内存里，除非另做换入换出 | 「速度像 13B」不等于「显存像 13B」 |

笔记还把滑动窗口注意力和分组查询注意力写在同一模型里。那是注意力怎么看过去、KV 缓存怎么共享，和「有几个专家」是分开的开关。滑动窗口决定能回看多远；GQA 让多头共享 KV，降低缓存。把这三件事说成「MoE 所以能读长文档」，是把三笔账并成了一句。

### 3. 它不修补 Day06 的链路

查询里没有颐和园、片段放错位置、两个代理各写一个价格，换 top-2 专家都还在。MoE 改变的是每个 token 的前馈计算由谁完成。事实仍来自权重里的统计和这一次的条件。

## 五、四列表：先问要改的是哪一笔

| 要改变的东西 | 放在哪一笔账 | 对得上的手段 | 冒充者 |
|---|---|---|---|
| 这次回答必须出现的新事实 | 条件 | 检索、工具结果原文写回 | 微调、加温度、加一个没看到证据的审核代理 |
| 稳定的格式、口吻、工具 JSON | 权重邻域 | 少样本；若必须跨请求稳定，再微调并补释义 | 把格式要求只写在一份谁也不读的文档里 |
| 单次能看见的原文长度 | 窗口容量 | 长上下文，并用金段落对照中间是否还读得到 | 以为窗口变大等于读完 |
| 每个 token 的计算和显存 | 激活参数 / 常驻专家 | MoE 或稠密小模型，两笔账分开报 | 8 专家等于 8 倍智能 |
| 谁来执行搜索和改文件 | 运行时 | 工作流或带观察的循环 | 在提示词里写「请调用工具」但没有暂停点 |

Day06 的停止条件仍然优先于这张表。链路停在查询缺失时，不进入微调，也不进入 MoE。

## 六、本日核心认知

1. **预训练不是空的。** 缺的是私有、时效和不稳定的具体事实，不是全部专业知识。
2. **微调覆盖训练说法的邻域。** 说法一偏，生成退回。释义是在扩大邻域，不是在背知识库。
3. **QLoRA 的四件做法都在显存和适配器上。** 99.3% 是一次 GPT-4 打分，数据质量先于条数。
4. **P-Tuning 训练的是连续提示。** 主干可以冻结，知识库不会因此进入主干。
5. **长上下文提高容量。** 中间证据是否被用到，用金段落对照，不看窗口数字。
6. **MoE 的路由是 top-k 前馈。** 46.7B 总参数、12.9B 激活、显存另算。滑动窗口和 GQA 是另外的账。
7. **三个旋钮都不执行工具，也不改写查询。** 那些仍然在 Day03 到 Day05 的条件账和运行时账里。
