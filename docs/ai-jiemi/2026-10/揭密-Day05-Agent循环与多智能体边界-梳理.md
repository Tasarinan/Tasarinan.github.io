## 一、智能体是带暂停点的生成

初级定义是「能规划、有记忆、会用工具的模型」。拆开之后，模型仍然只生成 token。新的结构是 Day04 的暂停点被产品化了。

```text
决定    模型写出下一步的文本
执行    运行时对世界产生副作用
记录    副作用的结果写回上下文
继续    模型条件于这段记录
```

**关键洞察：少任何一行，系统就退回另外两类。** 没有「决定」，只是人把工具绑死的工作流。没有「执行」，只是聊天。没有「记录」，下一步会条件于一个没发生的结果。

四件套可以继续用，但每件都要标位置：规划在文本里，记忆在库里，工具在运行时里，行动若改变外部世界，就不在前向传播里。

## 二、多智能体的变量是上下文副本，不是智能的个数

每增加一个代理，就增加一份上下文副本和一条生成路径。副本之间不会自动一致。

| 你希望的效果 | 副本必须满足的条件 | 笔记里的反例 |
|---|---|---|
| 并行阅读，扩大覆盖 | 各副本可以看不同材料；收口的人要看见材料来源 | 任务书含糊，多个子代理重复搜同一件事 |
| 并行修改同一工件 | 各副本看见同一条决策链，写入可以合并 | 代码编辑里两个代理对同一文件做了不同的隐含决定 |
| 节省窗口 | 用摘要代替原文 | 摘要丢掉的约束，后续步骤不再遵守 |

Anthropic 的 90.2% 和 15 倍 token 放在第一行。Cognition 的单线程放在第二行。第三行是单线程写满窗口之后的妥协，不是免费的记忆。

选型顺序因此是固定的：

1. 是不是一句带证据的问答。是就停在 Day03。
2. 步骤是否已知。是就写工作流。
3. 是否要在共享工件上连续写。是就单线程。
4. 是否是可并行的阅读。是才拆子代理，并给任务书、工具边界和引用收口。

## 三、记忆的淘汰规则就是下一步看不见什么

六类名词里，真正影响第二天行为的是淘汰：

1. 滑出窗口的对话，等于没发生。
2. 没写进日志的工具结果，无法复盘，也无法恢复。
3. 源文档更新后，索引里的旧片段仍会被当成事实。
4. 技能说明若能被闲聊改写，程序记忆就和情节记忆混在一起，下一步的做法会漂。

**和检索的同构**：Day03 说证据要放进条件才存在。记忆是跨请求版本的同一句话。没读出来的长期记忆，对这次生成等于不存在。

## 四、本日核心认知

1. **用三问给系统命名。** 谁决定下一步，谁执行工具，失败能否从该步恢复。
2. **Function Calling 训练的是格式。** 副作用仍在运行时。
3. **多代理等于多份上下文。** 读可以并行，共享写入要决策链。
4. **内部提升数字要和 token 倍数一起读。** 任务形态换了，数字作废。
5. **记忆是读写和淘汰。** 对不上存储的分类不进架构图。
6. **压缩用细节换窗口。** 被压掉的约束不会在下一步复活。
