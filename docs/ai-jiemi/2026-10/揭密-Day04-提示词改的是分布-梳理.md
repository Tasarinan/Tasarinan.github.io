## 一、提示工程是在排列 token，不是在训练

| | 提示工程 | 微调 |
|---|---|---|
| 改哪里 | 这一次的上文 | 权重 |
| 生效范围 | 这一次请求，或所有带这段提示的请求 | 之后所有请求，直到再训练 |
| 离开训练说法时 | 分布跟着新条件走 | 笔记里的现象是退回原来的生成 |
| 失败形态 | 该段条件没把路径拉过去 | 新说法不在微调邻域里 |

**关键洞察：提示词的迭代单位是一段条件，不是一句文案。** 分隔、样例、步骤、输出起句，各自对应一段可以指认的 token。指认不出的句子（奖励、惩罚、自然一点）就不要和前一类混在同一轮实验里。

上下文工程笔记把这件事又往外推了一步：提示工程优化「怎么写」，上下文工程决定「写什么进窗口」——参数表、差评、竞品摘要按相关度放进来，而不是把库整段搬进来。Day03 的拼接和 Day04 的指令是这件事情的两截。只优化两截中的一截，另一截仍会用位置和干扰把分布拉走。

## 二、思维链是延迟提交，不是新的推理引擎

模型没有一个隐藏的草稿区。所谓逐步思考，就是草稿以 token 的形式进入上下文。好处是最后一步能看见草稿。代价是草稿里的错误和正式答案享有同样的条件地位。

所以思维链适合中间步可以被输入核对的任务：计数、引用、按原文抽取、算术。不适合用草稿去生产没有来源的事实，再把草稿当证据。

少样本加思维链，是把「草稿长什么样」也放进条件。比单独一句「请逐步思考」更具体。

## 三、ReAct 把运行时插进自回归环

```text
Day01 的环：  前向 → token → 接回上下文
ReAct 的环：  前向 → Action 文本 → 暂停
              → 运行时执行 → Observation 接回上下文 → 再前向
```

暂停点是架构边界。边界里面是分布，边界外面是工具的真实返回。工具名、参数、空结果、错误栈，都以文本回到边界里面。模型无法区分「工具说没找到」和「程序忘了把没找到写上」，除非文本里真的有那句话。

**三条纪律**：

1. Action 文本必须能被解析，否则运行时没有可执行的动作。
2. Observation 使用工具的原文，不经过另一段无来源的润色。
3. 轨迹要保留三行。框架的封装不能拿掉这三行。

Day05 会把多个这样的环拼在一起。拼之前，单个环的三行必须先能对上。

## 四、本日核心认知

1. **提示词排列条件。** 权重的事留给微调。
2. **能指认的 token 才能做实验。** 分隔、样例、步骤、起句属于这类。
3. **奖励和惩罚在推理时没有对应项。** 它们不和分隔符放在同一轮对照里。
4. **否定句先把被禁内容写进条件。** 能用输出骨架表达的，用骨架。
5. **思维链把草稿公开成 token。** 草稿会滚雪球。
6. **ReAct 的行动在暂停点之外。** 空观察必须可见。
